Część 1 — Kluczowe pojęcia

Cookie (ciasteczko) Mały kawałek danych który serwer wysyła do przeglądarki. Przeglądarka przechowuje go i automatycznie dołącza do każdego kolejnego żądania — bez żadnej akcji użytkownika. Używane do sesji (wiedza kto jest zalogowany) i tokenów CSRF.

Przykład — nagłówek odpowiedzi serwera:
Set-Cookie: XSRF-TOKEN=abc123; Path=/; SameSite=Lax
Set-Cookie: laravel_session=xyz789; HttpOnly; Path=/
Sesja Laravel tworzy unikalną sesję dla każdego odwiedzającego i przechowuje jej ID w cookie (laravel_session). Rzeczywiste dane sesji (kto jest zalogowany) żyją po stronie serwera. Cookie to tylko klucz do szafki — szafka z danymi jest na serwerze.
CSRF — Cross-Site Request Forgery (fałszerstwo żądań między stronami) Atak w którym złośliwa strona nakłania Twoją przeglądarkę do wysłania żądania na inną stronę, na której jesteś zalogowany. Przykład: jesteś zalogowany w banku, wchodzisz na złą stronę — ta cicho wysyła POST na endpoint "przelew" Twojego banku używając Twoich ciasteczek sesji.

Jak Laravel to blokuje: Serwer generuje sekretny token (XSRF-TOKEN) i wkłada go do cookie. Każde żądanie POST/PUT/DELETE musi ten token przesłać też w nagłówku (X-XSRF-TOKEN). Zła strona nie może odczytać Twoich cookie przez JavaScript bo jest na innej domenie. Laravel odrzuca każde żądanie zmieniające stan bez poprawnego tokenu.
XSRF-TOKEN vs laravel_session — różnica
CookieCo przechowujeKto czytaHttpOnly
XSRF-TOKENToken ochrony CSRFJavaScript odczytuje i wysyła jako nagłówekNIE — celowo dostępny dla JS
laravel_sessionID sesjiPrzeglądarka wysyła automatycznieTAK — JS nie może go odczytać (bezpieczniejszy)
Sanctum SPA (Stateful API) Laravel Sanctum w trybie SPA używa ciasteczek zamiast tokenów API. Frontend (przeglądarka) loguje się raz, dostaje cookie sesji, i każde kolejne żądanie API jest automatycznie uwierzytelnione bo przeglądarka wysyła cookie. Nie ma potrzeby przechowywania tokenu w localStorage. To podejście użyte w ARTIKULA.

Konfiguracja w tym projekcie:
app/bootstrap/app.phplinie 16–19
->withMiddleware(function (Middleware $middleware): void {
    $middleware->statefulApi();
    $middleware->redirectGuestsTo(fn (Request $request) => $request->is('api/*') ? null : '/login');

→statefulApi() — włącza middleware Sanctum który inicjalizuje sesję dla żądań z zaufanych domen
→redirectGuestsTo(null dla api/*) — niezalogowane żądania API dostają 401 JSON zamiast przekierowania na stronę logowania

Część 2 — Manualne testy w terminalu (curl)

Te testy robiliśmy ręcznie przez terminal żeby zweryfikować że API działa, zanim napisaliśmy automatyczne testy. Każda komenda curl to żądanie HTTP wysyłane z terminala.

Flow XSRF — krok po kroku

Każde żądanie zmieniające stan (POST, PUT, DELETE) wymaga tego 2-krokowego flow:

1
GET /sanctum/csrf-cookie — prosimy Laravel o ustawienie cookie XSRF-TOKEN
2
Odczytujemy cookie — wyciągamy wartość tokenu z zapisanego pliku cookies
3
POST /api/login (lub register itp.) — wysyłamy token jako nagłówek X-XSRF-TOKEN

Krok 1 — Pobierz cookie CSRF

curl -s -c cookies.txt \
  -H "Origin: http://127.0.0.1:8000" \
  http://127.0.0.1:8000/sanctum/csrf-cookie
→-s — tryb cichy, ukrywa pasek postępu pobierania
→-c cookies.txt — zapisz cookie które serwer wyśle do pliku cookies.txt
→-H "Origin: ..." — mówi Sanctum że żądanie pochodzi ze zaufanej domeny stateful. Bez tego Sanctum nie inicjalizuje sesji i kolejne żądanie wyrzuca błąd "Session store not set on request"

Krok 2 — Wyciągnij token (URL-dekoduj)

XSRF=$(grep XSRF-TOKEN cookies.txt | awk '{print $7}' | sed 's/%3D/=/g; s/%2B/+/g; s/%2F/\//g')
→grep XSRF-TOKEN cookies.txt — znajdź linię z tokenem w pliku
→awk '{print $7}' — weź 7. kolumnę (wartość tokenu)
→sed 's/%3D/=/g' — URL-dekodowanie: token jest zakodowany, %3D to =, %2B to +, %2F to /. Laravel waliduje surowy token, nie URL-zakodowany.
→Wynik jest zapisany w zmiennej shell $XSRF
W prawdziwej przeglądarce to dekodowanie robi JavaScript automatycznie. W curl musieliśmy to zrobić ręcznie — dlatego testy curlowe są bardziej skomplikowane niż to co dzieje się w przeglądarce.

Krok 3 — Zarejestruj użytkownika

curl -s -b cookies.txt -c cookies.txt \
  -X POST http://127.0.0.1:8000/api/register \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -H "Origin: http://127.0.0.1:8000" \
  -H "X-XSRF-TOKEN: $XSRF" \
  -d '{"email":"krystian@test.com","password":"Artikula!2026"}' | json_pp
→-b cookies.txt — wyślij zapisane wcześniej cookie (sesja + XSRF)
→-c cookies.txt — zapisz też nowe cookie które serwer zwróci (sesja regeneruje się po logowaniu)
→-X POST — to jest żądanie POST
→-H "Content-Type: application/json" — mówi serwerowi że ciało żądania to JSON
→-H "Accept: application/json" — mówi Laravel żeby zwracał błędy jako JSON zamiast HTML
→-H "X-XSRF-TOKEN: $XSRF" — token CSRF który wyciągnęliśmy. Laravel sprawdza czy pasuje do sesji.
→-d '{...}' — ciało żądania (email + hasło)
→| json_pp — pipe: przekazuje odpowiedź do json_pp który ładnie formatuje JSON

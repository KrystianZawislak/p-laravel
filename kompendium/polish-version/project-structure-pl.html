ARTIKULA — Struktura projektu i stack

Czym jest każda technologia, do czego służy każdy plik i jak to wszystko ze sobą współpracuje

Część 1 — Stack technologiczny

PHP — język programowania PHP to język w którym napisany jest backend. Działa po stronie serwera. Kiedy przychodzi żądanie (np. POST /api/login), serwer wykonuje kod PHP, rozmawia z bazą danych i zwraca odpowiedź. PHP jest najstarszym i najbardziej rozpowszechnionym serwerowym językiem — napędza WordPress, Wikipedię, oryginalny kod Facebooka. Tu używamy wersji 8.5 (przez Laravel Herd).
Laravel — framework PHP Laravel to zestaw gotowych narzędzi i konwencji do budowania aplikacji webowych w PHP. Zamiast pisać surowe PHP od zera (ręczne łączenie z MySQL, ręczna walidacja, ręczne odpowiedzi HTTP), Laravel dostarcza: routing, walidację żądań, ORM, uwierzytelnianie, sesje, infrastrukturę testową i wiele więcej. Myśl o nim jak o rusztowaniu. Tu używamy wersji 13.
Composer — menadżer paczek PHP Composer pobiera i zarządza bibliotekami PHP. Jak npm dla Node lub pip dla Pythona. Kiedy uruchamiasz composer install, czyta composer.json i pobiera wszystkie wymienione paczki do folderu vendor/. Plik composer.lock blokuje dokładne wersje żeby każdy developer dostał ten sam kod.
MySQL — relacyjna baza danych MySQL przechowuje trwałe dane: użytkowników, wizyty, usługi. Dane są zorganizowane w tabelach z wierszami i kolumnami — jak arkusze kalkulacyjne połączone kluczami obcymi. Aplikacja rozmawia z MySQL przez Eloquent ORM. Tu używamy wersji 9.6 (przez Homebrew).
Laravel Sanctum — biblioteka uwierzytelniania Sanctum to paczka Laravel obsługująca sesje logowania. W trybie SPA (stateful) — tym który tu używamy — działa przez ciasteczka: przeglądarka dostaje ciasteczko laravel_session po zalogowaniu i wysyła je automatycznie przy każdym kolejnym żądaniu. Nie potrzeba tokenów API. Ciasteczko XSRF-TOKEN to dodatkowa warstwa ochrony CSRF.
Eloquent ORM — warstwa abstrakcji bazy danych ORM to Object-Relational Mapper. Eloquent pozwala pracować z rekordami bazy jako obiektami PHP zamiast pisać surowy SQL. Appointment::where('user_id', 1)->get() to Eloquent — generuje SELECT * FROM appointments WHERE user_id = 1 za kulisami, jako PDO prepared statement (bezpieczne na SQL injection).
PHPUnit — framework testowy PHPUnit uruchamia automatyczne testy. Laravel owija go pomocnikami jak postJson(), actingAs() i assertStatus(). Testy działają na tymczasowej bazie SQLite w pamięci — nigdy nie dotykają twoich danych MySQL. Komenda: php artisan test.

Część 2 — Przepływ żądania

Co się dzieje kiedy przeglądarka wysyła POST na /api/appointments:

1
public/index.php — punkt wejściaLaravel bootuje z tego jednego pliku. Każde żądanie HTTP — bez względu na URL — trafia tu najpierw. Ładuje framework i przekazuje kontrolę do routera.
2
bootstrap/app.php — middlewareSanctum stateful middleware sprawdza: czy żądanie ma poprawne ciasteczko sesji? Jeśli nie — 401. Jeśli tak — zalogowany użytkownik jest wczytywany. Tu też sprawdzany jest token CSRF.
3
routes/api.php — dopasowanie trasyRouter sprawdza: która metoda kontrolera obsługuje POST /api/appointments? Odpowiedź: AppointmentController@store. Tu też sprawdzany jest limit throttle.
4
Requests/StoreAppointmentRequest.php — walidacjaZanim kontroler się uruchomi, Form Request waliduje każde pole. Data w przeszłości? Odrzuć. Godzina spoza listy? Odrzuć. Termin zajęty? Odrzuć. Więcej niż 3 wizyty? Odrzuć. Jeśli cokolwiek nie przejdzie → odpowiedź 422 JSON jest wysyłana natychmiast.
5
Controllers/AppointmentController.php — logika biznesowaMetoda store() się uruchamia. Wywołuje Appointment::create([...]). Gotowe.
6
Models/Appointment.php — Eloquent zapisuje do MySQLModel tłumaczy obiekt PHP na instrukcję INSERT SQL i wykonuje ją przez PDO. Nowy rekord jest zwracany.
7
Odpowiedź JSON wysyłana do przeglądarkireturn response()->json($appointment, 201) — nowa wizyta jest serializowana do JSON i odsyłana z HTTP 201 Created.

Część 3 — Mapa plików i folderów

Wszystkie komendy (php artisan, composer) uruchamia się z folderu p-laravel/app/.

BACKEND — app/  (kod który TY piszesz)
Http/Controllers/AppointmentController.phpCRUD wizyt — index, store, update, destroy. Wywołuje modele i zwraca JSON.
Http/Controllers/AuthController.phpRejestracja, logowanie, wylogowanie. Zarządza sesją Sanctum.
Http/Requests/StoreAppointmentRequest.phpWalidacja wizyt: data, godzina, tryb, limit 3, konflikt terminów. Uruchamia się automatycznie przed kontrolerem.
Http/Requests/RegisterRequest.phpWymagania przy rejestracji: unikalny email, silne hasło (min 8 znaków, nieszkompromitowane).
Http/Requests/LoginRequest.phpEmail i hasło są wymagane przy logowaniu.
Http/Requests/UpdateAppointmentRequest.phpTe same reguły co StoreAppointmentRequest, używane przy edycji wizyty.
Models/User.phpMapuje tabelę users. Cast 'password' => 'hashed' automatycznie hashuje hasło bcryptem.
Models/Appointment.phpMapuje tabelę appointments. Relacje: belongsTo User, belongsTo Service.
Models/Service.phpMapuje tabelę services. Tylko odczyt — usługi są wstawiane przez seeder.
Policies/AppointmentPolicy.phpSprawdza czy user_id === auth()->id() przy edycji i usuwaniu. Ochrona przed IDOR.
Providers/AppServiceProvider.phpRejestruje AppointmentPolicy w Laravelu żeby $this->authorize() działało.
FRONTEND — public/  (dostępne bezpośrednio z przeglądarki)
public/index.htmlStrona główna — hero, usługi, opinie, formularz rezerwacji. Cały interfejs aplikacji.
public/login.htmlFormularz logowania. Wysyła POST /api/login przez Sanctum SPA.
public/register.htmlFormularz rejestracji. Wysyła POST /api/register.
public/app.jsCały frontend JS (~450 linii). jQuery + fetch API. Obsługuje auth, CRUD wizyt, animacje, marquee.
public/styles.cssCały CSS — kolory, animacje, układ responsywny, zmienne CSS.
public/frames/35 klatek JPG (f00.jpg–f34.jpg) do animacji ust w sekcji hero. Sterowane scrollem.
public/index.phpPunkt wejścia Laravel. Każde żądanie HTTP przechodzi przez ten plik. Nie edytować.
BAZA DANYCH — database/
migrations/Historia struktury bazy w git. Każdy plik to jeden krok: tworzenie tabeli users, services, appointments. Uruchamiane przez php artisan migrate.
seeders/DatabaseSeeder.phpWstawia 6 usług logopedycznych przy pierwszym setupie. Uruchamiany przez --seed.
factories/UserFactory.phpGenerator fałszywych użytkowników. Używany TYLKO w testach PHPUnit (User::factory()->create()).
database.sqlitePlik bazy SQLite. Używany TYLKO przez testy — w pamięci, izolowany od MySQL.
ROUTING I KONFIGURACJA
routes/api.phpDefinicja wszystkich endpointów /api/*: register, login, logout, user, appointments CRUD. Middleware throttle i auth:sanctum.
routes/web.phpSerwuje pliki HTML dla tras /, /login, /register.
bootstrap/app.phpKonfiguracja middleware (Sanctum stateful, CSRF) i obsługa wyjątków (401 JSON dla API).
config/database.phpSterownik bazy (mysql), host, port, nazwa bazy. Czyta wartości z .env.
config/sanctum.phpLista zaufanych domen (stateful_domains). Musi zawierać domenę z której wysyłane są żądania.
phpunit.xmlKonfiguracja testów: baza SQLite w pamięci, BCRYPT_ROUNDS=4 (szybkie), SANCTUM_STATEFUL_DOMAINS.
TESTY — tests/Feature/
AuthTest.php6 testów: rejestracja (201), silne hasło (422), unikalny email (422), logowanie (200), złe hasło (401), brak sesji (401).
AppointmentTest.php9 testów: tworzenie (201), izolacja danych, IDOR (403), data z przeszłości (422), podwójna rezerwacja (422), zła godzina (422), limit 3 (422).
PLIKI GŁÓWNE
.envNIE w git. Sekrety: hasło do bazy, APP_KEY, SANCTUM_STATEFUL_DOMAINS. Każdy developer ma swój własny.
.env.exampleSzablon .env bez prawdziwych wartości. Jest w git — służy jako instrukcja dla nowego developera.
composer.jsonLista wymaganych paczek PHP i wersja PHP. Czytany przez composer install.
composer.lockJEST w git. Zamrożone wersje wszystkich paczek. Gwarantuje identyczny build na każdej maszynie.
.gitignoreLista plików pomijanych przez git: .env, vendor/, logi, cache.
vendor/NIE w git. Pobrane paczki Composer (Laravel, Sanctum, PHPUnit…). Odtwarzane przez composer install.
storage/logs/laravel.logLogi błędów i ostrzeżeń bezpieczeństwa (np. nieudane próby logowania — A09).

Część 4 — Rola każdego folderu w jednym zdaniu

Folder / PlikRola
app/Http/Controllers/Przyjmuje żądanie, wywołuje model, zwraca odpowiedź. Powinny być cienkie — bez logiki biznesowej.
app/Http/Requests/Waliduje każde przychodzące żądanie zanim kontroler je zobaczy. Jeśli niepoprawne, 422 jest zwracane automatycznie.
app/Models/Każda klasa reprezentuje jedną tabelę bazy. Wszystkie odczyty i zapisy do bazy przechodzą przez tutaj.
app/Policies/Reguły autoryzacji — "czy ten użytkownik może wykonać tę akcję na tym zasobie?" Wywoływane przez $this->authorize().
bootstrap/app.phpKonfiguracja aplikacji: które middleware zastosować, jak obsługiwać wyjątki.
config/Ustawienia frameworka dla bazy danych, sesji, maila itp. Tylko do odczytu w trakcie działania.
database/migrations/Historia schematu bazy danych pod kontrolą wersji. Uruchamiane przez php artisan migrate.
database/seeders/Wstawiają dane startowe/testowe do bazy. Uruchamiane z flagą --seed przy migrate.
database/factories/Generatory fałszywych danych tylko dla testów. Używane przez User::factory()->create() w PHPUnit.
public/Jedyny folder który serwer webowy udostępnia. Wszystkie pliki dostępne przez przeglądarkę (HTML, JS, CSS) są tu.
routes/api.phpDefiniuje każdy endpoint API: URL, metoda HTTP, który kontroler go obsługuje, które middleware jest stosowane.
storage/logs/Pliki logów zapisywane przez aplikację w trakcie działania. laravel.log przechwytuje błędy i ostrzeżenia bezpieczeństwa.
tests/Feature/Automatyczne testy integracyjne. Każdy test symuluje pełne żądanie HTTP i sprawdza odpowiedź oraz stan bazy.
vendor/Wszystkie pobrane paczki Composer (Laravel, Sanctum, PHPUnit…). Ignorowane przez git. Odtwarzane przez composer install.
.envSekrety specyficzne dla środowiska: hasło bazy, klucz aplikacji, konfiguracja domeny. Nigdy nie commitowane do git.
composer.lockDokładne wersje każdej paczki. Commitowane do git — zapewnia reprodukowalne buildy na każdej maszynie.
phpunit.xmlKonfiguracja PHPUnit: jaka baza dla testów, nadpisania zmiennych środowiskowych (SQLite, BCRYPT_ROUNDS).

Część 5 — Czego NIE ma w tym projekcie, a normalnie jest w Laravel

Standardowa aplikacja Laravel ma więcej funkcji. Celowo je pominęliśmy bo nie były potrzebne:

FunkcjaDlaczego pominięta
Szablony Blade (resources/views/)Frontend to zwykły HTML w public/ — nie potrzeba szablonów renderowanych po stronie serwera
Vite / Node.js build stepBrak bundlowania JS — frontend używa vanilla JS + CDN jQuery, nie ma npm run build
Kolejki i zadania (database/jobs)Brak zadań w tle w tym projekcie
Wysyłanie emailiBrak email_verified_at — rejestracja nie wymaga weryfikacji emaila
Tokeny API (Bearer tokens)Używamy cookie-based Sanctum SPA — bardziej odpowiedni dla frontendu przeglądarkowego
System ról / uprawnieńJeden typ użytkownika — brak admina, brak potrzeby ról
